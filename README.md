# 羽毛球场地预约脚本（桌面版）

> 这是一个**本地电脑运行**的小工具，核心思路是：
> 1. 你先在界面里选好“后天 + 场地 + 时间段”；
> 2. 提前把预约接口参数准备好；
> 3. 到了晚上 `23:00:00` 自动高频发送请求，提升抢场成功率。

## 先说明（重要）
你给的链接是微信小程序短链，无法直接在普通浏览器里完整自动化“点点点”流程。这个版本采用了一个折中且更稳定的方案：

- 直接调用预约接口（HTTP API）进行抢场；
- 你需要先抓到一次真实预约请求（URL / Headers / Body），再填入本工具；
- 脚本会在指定时间自动重试多次。

如果你后续能提供**明确的预约接口字段**，我可以再帮你把模板做成“几乎零配置”。

---

## 功能
- 图形界面（Tkinter）填写参数。
- 自动计算后天日期（可手动改）。
- 选择场地（1~6）和时间段（15:00~21:00共6段）。
- 支持预约前“立即测试发送1次”。
- 支持定时到点（默认23:00:00）自动抢场。
- 支持配置落盘到 `booking_config.json`。
- 支持从 HAR 抓包自动提取候选请求并生成配置（`har_to_booking_config.py`）。

## 你说“抓不到参数”时，怎么做（重点）

你现在最需要的是拿到**一条真实的预约请求**。下面是最实用方案。

### 方案 A：手机抓包 + HAR 导出（推荐）

1. 在电脑安装 Charles / Proxyman（任选）。
2. 手机和电脑连同一个 Wi-Fi。
3. 手机设置 HTTP 代理为电脑 IP + 端口。
4. 手机安装并信任抓包证书。
5. 打开小程序，走一遍“选择场地时间 -> 提交预约”。
6. 在抓包工具中过滤域名（比如 `xcx-api.zuduijun.com`），导出 HAR。

然后执行：

```bash
python har_to_booking_config.py --har /path/to/your.har --host-keyword xcx-api.zuduijun.com
```

脚本会：
- 按评分列出候选请求（通常第 0 条就是最像预约提交）；
- 自动生成 `booking_config.json`；
- 你再打开 GUI 点“立即测试发送1次”验证。

如果第 0 条不对，可以改 `--pick`：

```bash
python har_to_booking_config.py --har /path/to/your.har --pick 1
```

### 方案 B：抓不到 HTTPS 内容时

如果你只能看到 `CONNECT`、看不到请求体，常见原因是证书没完全信任或 App 做了证书校验。

你可以：
- 先确认手机系统层面“证书已信任”；
- 改用另一款抓包工具再试（有些 ROM 对证书兼容更好）；
- 优先保证能抓到“你曾经成功预约那一次”的请求（哪怕只抓到部分字段也有用）。

### 方案 C：导出 cURL 再手动回填

如果你的工具支持“Copy as cURL”，你可以把 cURL 里的：
- URL
- Headers（`-H`）
- Body（`--data-raw`）

拆出来填进 GUI。

## 你需要准备什么

在手机上完成一次“正常预约”并抓包（如 Charles / mitmproxy / 代理日志），拿到：

1. 预约接口 URL（例如 `https://xxx/booking/create`）
2. Headers（特别是 token、cookie、签名字段）
3. Body JSON（预约日期、场地、时间段等字段）

把这三项填进 GUI：

- `预约接口 URL` -> 请求地址
- `Headers(JSON)` -> 完整请求头
- `Body模板(JSON)` -> 用占位符替换可变字段

支持占位符：
- `{date}` 目标日期（默认后天，如 `2026-04-17`）
- `{court}` 场地编号（1~6）
- `{time_slot}` 时间段字符串（如 `18:00-19:00`）
- `{slot_start}` 开始时间（如 `18:00`）
- `{slot_end}` 结束时间（如 `19:00`）

## 使用顺序（按这个做）

1. （首次）抓包导出 HAR。
2. 执行 HAR 转配置：
   ```bash
   python har_to_booking_config.py --har /path/to/your.har --host-keyword xcx-api.zuduijun.com
   ```
3. `python booking_bot_gui.py` 打开界面。
4. 复核 URL / Headers / Body 模板（尤其 token/sign）。
5. 选择场地与时间段（你想打的那一档）。
6. 点 `立即测试发送1次`，确认接口可用、返回正常。
7. 把执行时间设为 `23:00:00`（或你想提前几秒，比如 `22:59:58`）。
8. 点 `开始定时`。
9. 到点后程序自动重试发送（次数和间隔可调）。

---

## 参数建议
- 重试次数：20~60
- 间隔：80~200ms

一般建议从：
- 重试次数 `30`
- 间隔 `120ms`

开始，根据服务器限流再微调。

## 常见问题

### 1) 返回 401 / 403
通常是 token / cookie 过期。需要在接近23点前重新抓一次最新请求头。

### 2) 返回“签名错误”
说明请求里有动态签名参数。需要把签名算法补进脚本（你提供样本后我可继续完善）。

### 3) 返回“已被预约”
说明被别人抢先。可尝试减少间隔、提前1~2秒开始发请求。

### 4) HAR 里候选太多，不知道选哪个
优先选：
- `POST` 请求；
- URL 含 `book/reserve/order` 关键词；
- 请求体里有 `date/court/time` 类字段。
